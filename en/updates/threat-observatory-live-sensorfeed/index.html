DEVELOPMENT TRANSMISSION // SECURITY-03

Threat Observatory with real sensor feed live

The isolated JARVIS honeypot, signed privacy uplink, enlarged world map, and hourly GitHub/Discord ledger are now end-to-end active.

01 // SECURITY-03

Separate sensor zone instead of show server

The public sensor runs in its own trust zone without direct access to the website, Discord bots, or internal project data. It emulates an SSH service in a controlled manner and has a documented emergency stop, restart, and health check path. The goal is observation and research—not hacking back foreign systems.

02 // SECURITY-03

Minified and signed data chain

Events locally pass through a sanitizer and then an HMAC-signed receiver with replay protection, rate limit and strict field allowlist. Raw IP addresses, credentials, full inputs, commands, URLs, payloads, and malware files are not publicly transmitted. A network pseudonym is expressly not a personal identity.

03 // SECURITY-03

Real geo/ASN data with rough privacy boundaries

Country and network operator are determined exclusively locally from a versioned DB-IP-Lite database. Before the uplink, positions are reduced to a two-degree grid; missing assignments remain N/A. The location of the JARVIS sensor is also only shown as a generous region.

04 // SECURITY-03

Larger map and real signal lines

The Threat Observatory uses real public RIPE Atlas infrastructure points, a dated DShield snapshot, and authenticated events from its own sensor. Direct lines to the JARVIS sensor only arise from real, permissibly roughly located sensor events. The card can look like a hacker film - the data underneath remains comprehensible and honest.

05 // SECURITY-03

GitHub ledger and silent Discord feed

For actual data changes, GitHub publishes a strictly validated, sanitized ledger no more than hourly. A separate Discord webhook reports the same status without mentions in the JARVIS news channel and links to the public history. A controlled real sensor change was completely removed down to the visible Discord embed.

06 // SECURITY-03

What this milestone doesn't mean

The system does not claim the identity of an attacker or a compromised third-party host. The public view is not a full scan of the Internet. Further work includes long-term monitoring, optional additional provider firewall rules, and clean operational and recovery testing.
